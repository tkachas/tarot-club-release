# Бимбо карты: правила для кодовых агентов

## Задача и границы

Это небольшое личное приложение для общей колоды Таро и журнала гаданий на `bimbochka.ru`. Владелец описывает желаемый результат обычным языком; редактор работает через Codex или Claude Code. Помогайте превратить запрос в работающий, понятный интерфейс. Если неясно, как должна вести себя функция, уточните это до изменения данных или публичного поведения.

Репозиторий содержит **код**, а не записи пользователей. Рабочая база SQLite находится только на VDS в `/home/deploy/tarot-club/data/`. Публикация из GitHub пока ручная. Обычные задачи по интерфейсу и логике заканчиваются pull request, а не изменением сервера.

## Карта проекта

- `public/index.html` — разметка и подписи.
- `public/styles.css` — новые стили; файл импортирует `public/original.css`, извлечённый из исходной страницы. Предпочитайте изменения в `styles.css`.
- `public/app.js` — интерфейс, запросы к API, обновление общего состояния.
- `public/cards.json` и `public/cards/` — 78 карт. `id` карты от 0 до 77 соответствует изображению от `01.jpg` до `78.jpg`. Сохраняйте это соответствие.
- `server.mjs` — HTTP API, проверка запросов и схема SQLite. Сервер слушает только `127.0.0.1:3000`; Caddy с `basic_auth` и HTTPS стоит перед ним.
- `test/server.test.mjs` — проверка API, конфликтов и сохранности данных после перезапуска.
- `README.md` — запуск, резервное копирование и ручное обновление VDS.

Здесь нет сборки и сторонних npm-пакетов. Для разработки используйте Node.js 24. Исходный большой HTML-файл, из которого получены картинки и стили, в репозитории отсутствует.

## Как выполнять изменение

1. Найдите затронутые файлы и кратко объясните редактору, что поменяется для посетителя.
2. Делайте небольшое изменение по запросу; сохраняйте русские подписи и существующий визуальный стиль, если не попросили иное.
3. Для UI проверьте страницу в браузере, в том числе узкий экран, добавление и редактирование записи. Для API проверьте успешный сценарий и ошибки.
4. Перед PR выполните `node --check server.mjs`, `node --check public/app.js` и `node --test test/server.test.mjs`. При изменении поведения API обновите тест, чтобы он проверял новый результат.
5. В PR напишите простыми словами: что увидит пользователь, как проверено, затронуты ли данные. Для видимых изменений приложите снимок экрана.

## Важные ограничения

- Не добавляйте в Git базу `data/`, ключи SSH, пароли, хеш Caddy, `.env` и резервные копии.
- Не удаляйте и не пересоздавайте рабочую базу. Изменение схемы требует миграции существующих данных и отдельной инструкции по резервной копии.
- Не убирайте проверку CSRF, ограничение размера запросов, экранирование пользовательского текста и привязку сервера к localhost.
- Общий логин Caddy даёт всем участникам одинаковые права. Поле «Ваше имя» — подпись, а не учётная запись. Не создавайте видимость отдельных прав без настоящей серверной авторизации.
- Не меняйте `activate-on-vds.sh`, `tarot-club.service`, `Caddyfile.example` и способ публикации для обычной задачи по UI. Изменения инфраструктуры согласуйте с владельцем отдельно.
- Не запускайте деплой и не меняйте VDS при работе над PR. Владелец проверит и опубликует принятую версию.
